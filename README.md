# 扬扬成长助手 · 微信 / 手机浏览器版 V1.0

> 当前为可运行的 H5/PWA 前端应用，而不是已注册发布的微信原生小程序。

## 已实现

- 喂奶快捷记录：配方奶、瓶喂母乳、亲喂母乳（可不填奶量）、混合喂养；本次奶量、追加补喂、备注、补录和编辑删除。
- 大小便快捷记录：尿尿、便便、都有；便便颜色、量、性状、备注。
- 其他护理记录：维生素 AD、体温观察、洗澡、抚触、用药等事件备注。
- 首页：当天累计奶量、过去 24 小时奶量、最后一餐时间、喂奶倒计时、当天时间轴。
- 历史：按真实自然日查看与修改，跨午夜按记录所选日期准确归档。
- 统计：最近 7 天奶量趋势、已记录日均奶量、尿便次数、相邻喂奶时间均值。
- 页面内提醒：手动开启、设置间隔和提前时间，页面运行且定时器正常时显示提示；关闭微信或后台时无法可靠推送。
- 隐私和离线：使用浏览器 localStorage 本地保存；在 HTTPS 环境首次访问后用 Service Worker 缓存静态页面，支持在支持的浏览器离线再次打开。
- 备份：导出 JSON / 合并导入 JSON；导入按记录唯一 id 去重。

## 如何运行

### 电脑本地测试

```bash
cd yangyang-care-web
python -m http.server 8080
```

打开 http://localhost:8080 。手机和电脑需在同一局域网才可通过本机 IP 访问，本机局域网访问通常不支持 PWA 离线缓存。

### 发布到互联网（供微信和 Safari 直接通过链接打开）

1. 新建 GitHub 仓库，例如 `yangyang-care`，上传本文件夹里的 `index.html`、`app.js`、`sw.js`、`manifest.webmanifest` 和 `assets` 目录。
2. 仓库设置 → Pages → Build and deployment → Deploy from a branch → 选择 `main` / `/(root)` → 保存。
3. 页面发布后，在地址 `https://你的用户名.github.io/yangyang-care/` 打开。复制此网址发到微信聊天中即可在微信内置浏览器打开。
4. iPhone Safari 可选择「分享」→「添加到主屏幕」，以类 App 方式打开。

**注意：** GitHub Pages 的可用性及微信对外链的访问政策可能随网络环境改变；若无法访问，可把静态文件部署到其他 HTTPS 静态站点。微信原生小程序需额外使用微信开发者工具开发、注册小程序、配置并审核发布。

## 数据安全与限制

- 所有新增数据默认**仅在当前浏览器本机保存**，不会在微信、Safari、其他手机间自动同步。
- 微信清理缓存、系统清理站点数据、隐私浏览或重装 App，都可能导致数据丢失；应定期在「设置」→「导出」进行 JSON 备份，并检查备份文件确实保存成功。
- 微信内置浏览器可能不支持直接下载 JSON；可尝试使用系统分享，或在 Safari 打开进行导出。
- 此版本不具备关闭页面后的可靠推送提醒。正式支持微信订阅消息需要后端、小程序授权、消息模板等；也可后续做 iOS 原生通知。
- 部分浏览器禁用第三方/本地存储时记录可能无法保存。
- 提醒间隔由用户设置，数据统计不构成医学建议。

## 如何导入已有43天照片的记录

现在**未把43张照片当作已核实的数字直接导入**。需要先逐条转录和人工核对，再生成 JSON。不要直接导入 `data/导入格式示例.json`：它仅演示字段结构，不是真实完整的历史数据。

一条喂奶记录示意：

```json
{"id":"unique-1","type":"feed","at":"2026-10-13T09:53","feedType":"formula","amount":150,"extra":0,"source":"historical","verified":true,"note":""}
```

一条大小便记录示意：

```json
{"id":"unique-2","type":"diaper","at":"2026-10-13T09:57","diaperType":"wet","stoolColor":"","stoolAmount":"","stoolTexture":"","source":"historical","verified":true,"note":""}
```

历史照片中存在跨午夜记载：例如写作10月13日的那页，10月12日傍晚的喂奶归入10月12日，10月13日凌晨以后归入10月13日。**具体以原始记录及用户确认的真实日期为准**，不应盲目批量套用到所有页面。模糊数据应标为 `verified:false` 并人工核对。

`{"version":1,"records":[...records...]}` 格式可以从「设置」→「导入」合并导入。App 还支持整个备份包的数据结构。
